# Project docs

These files are the durable context for the project.

## Start here

- [handoff.md](handoff.md) — current state and exact fresh-session pickup.
- [design.md](design.md) — product promise, interaction model, architecture,
  animation boundary, variable controls, and visual direction.
- [plan.md](plan.md) — current scope, risk spikes, implementation phases, and
  acceptance gates.
- [decisions.md](decisions.md) — compact log of choices that should outlive the
  current plan. Proposed entries stay proposed until the owner accepts them or
  implementation makes the choice explicit.

## Optional extension

## Documentation policy

- Edit `design.md` as the product and system evolve; it is the current truth,
  not a history book.
- Edit `plan.md` as work advances. Move to `docs/plans/` only if more than one
  substantial plan is active.
- Append or supersede decisions; do not rewrite their original rationale.
- Date research notes. Fold durable conclusions into design or decisions so
  execution never depends on rereading a research archive.
- Git is the history. Do not create review, issue, or status files until they
  improve coordination more than they cost in upkeep.
