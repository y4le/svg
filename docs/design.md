# Product and system design

## Product promise

This is a browser workbench for people who want SVG source and rendered
behavior in the same frame. It is deliberately code-forward: robust native
animation inspection, rendered-element navigation, and source-backed controls
make the code easier to understand and manipulate without hiding it. Code
remains the source of truth. The preview is not a second document; it is an
instrumented reading of the code.

The defining interaction is **one selection, two representations**. A cursor
inside an element marks the corresponding rendered geometry. Clicking visible
geometry reveals its authored opening tag and breadcrumb. Animation and
variables use that same link rather than living in disconnected inspectors.

Working positioning:

> Write SVG. See it move. Touch any element or variable and stay connected to
> the source.

GodSVG-class visual-first editing is a possible extension on this foundation,
not the core product definition. Its separate roadmap lives in
`docs/visual-editing-extension.md`.

## Audience and first jobs

Primary:

- front-end and design engineers hand-authoring icons, illustrations,
  diagrams, loaders, and micro-interactions;
- people debugging SVG generated by design tools or code;
- learners trying to understand the relationship between SVG markup and
  rendering;
- authors tuning a small family of parametric or animated assets.

First jobs:

1. Paste or open an SVG and understand which source created a visible part.
2. Change markup or CSS and see a stable live result.
3. Inspect, pause, and restart CSS or SVG animation.
4. Expose a few meaningful variables and tune them without losing exact values
   or source context.
5. Download the same ordinary SVG source.

## Principles

### Source stays sovereign

The editor stores text. Parsing, DOM, controls, outlines, and animation state
are derived. No background serializer rewrites whitespace, quote style,
attribute order, comments, IDs, or path data. Formatting and optimization are
explicit commands with a previewable diff, if they are added at all.

### One selection is the spine

Selection is a shared identity with an authored source range, a preview
element when one exists, and a textual ancestor breadcrumb. Features attach to
that identity: reveal code, outline geometry, follow `use`, list animations,
and eventually edit attributes.

### Extensions sit on the source core

The workbench does not pretend to be a full vector editor. It exposes stable,
versioned source ranges and source transactions so a visual-first editing layer
could be added later without becoming a second save authority. Do not build
element, geometry, path, or timeline systems in the core merely in anticipation
of that option.

### Preserve platform semantics

Prefer SVG, CSS custom properties, CSS animation, and SVG animation elements
over a project schema or runtime. The authored file should render without this
application.

### Make limitations visible

Invalid source shows a diagnostic and leaves the last valid preview visibly
stale. Generated instances map to their honest source owner. Disabled scripts
are reported. Inferred variable ranges are not presented as authored truth.

### Local and safe by default

Opening a file should not upload it, load its remote dependencies, execute its
scripts, or require an account. Recovery state may live in IndexedDB. Direct
filesystem handles are a progressive enhancement with download fallback.

### Quiet instrument, dense evidence

The workbench follows the Yale Thomas design language: warm dark surface,
type-led hierarchy, hairline structure, one restrained red link state, exact
values, and minimal boxes. Chrome recedes behind source, image, time, and
selection.

## MVP scope

### Included

- resizable source/preview split, with code left and preview right by default;
- CodeMirror XML editing, undo/redo, search, indentation, and line diagnostics;
- debounced last-known-good SVG preview with pan, zoom, fit, and selectable
  light/dark/checker backgrounds;
- bidirectional authored-element selection and ancestor breadcrumb;
- CSS animation and SVG animation element rendering;
- run/pause/restart, family detection, and a shared inspection-time scrubber;
- selected-element animation provenance with source navigation for supported
  SMIL and CSS declarations;
- local open/paste/download, dirty state, and crash/session recovery;
- root CSS custom-property discovery with exact value and unit controls;
- optional explicit range directives producing restrained sliders;
- keyboard access, reduced-motion behavior, and three-browser tests;
- examples covering static, CSS-animated, SMIL-animated, mixed, and parametric
  SVG.

### Explicitly out of the first MVP

- element insertion/reordering, freehand drawing, pen/path editing, resize
  handles, layers, alignment, and general WYSIWYG geometry editing;
- visual animation timeline, keyframe generation, easing curves, morph tools,
  or animation export conversion;
- arbitrary JavaScript execution or external runtime/CDN loading;
- AI generation/editing, accounts, cloud files, collaboration, comments, or
  telemetry;
- JSX, Lottie, raster, video, sprite, or design-tool export;
- automatic SVG optimization or whole-document formatting;
- general template expressions or variable substitution in arbitrary XML.

These are core-product boundaries. Structured visual editing and a
source-backed animation timeline are evaluated in a separate optional
extension; cloud suites, arbitrary script execution, and proprietary project
state remain out of scope.

## Core boundary and extension seam

The independently useful core is the linked source instrument:

- side-by-side editor and isolated browser preview;
- code ↔ rendered selection, ancestor/reference navigation, and last-good
  behavior during invalid edits;
- CSS/SMIL run, pause, restart, shared inspection time, and animation
  provenance;
- exact variable controls and explicitly bounded sliders.

This is the first MVP and the core roadmap. Its reusable seam is intentionally
small: immutable source versions, exact semantic ranges, one shared selection,
and version-checked source transactions. The optional visual editor can consume
those contracts, but owns its typed element/geometry/path projections and UI.
See `docs/visual-editing-extension.md` for its staged capability ladder.

## Workbench interaction

### Wide layout

```text
┌ filename.svg   valid · changed        01.42s  pause  restart  open  save ┐
├──────────────────────────────┬───────────────────────────────────────────┤
│ source                       │ preview                                   │
│                              │                                           │
│  <g id="orbit">              │             selected geometry             │
│    <circle ...>              │             thin red outline              │
│                              │                                           │
├──────────────────────────────┴───────────────────────────────────────────┤
│ svg › g#orbit › circle        radius  32 px  ─────────●────   period 1.8s │
└───────────────────────────────────────────────────────────────────────────┘
```

- The top rail uses text labels and values before icons. File/validity/dirty
  state stays stable at left; playback and file actions stay stable at right.
- The vertical split is one quiet hairline. Neither pane sits inside a card.
- The optional bottom rail combines breadcrumb, selected-element facts, and
  variables. It can be collapsed without changing the main frame.
- Narrow screens use explicit Source and Preview views with the same selection
  and bottom rail; they do not squeeze two unusable columns together.

### Selection behavior

- Cursor inside an opening tag, content, or closing tag selects the deepest
  authored element that owns that range.
- Preview click selects the deepest mapped authored element and reveals the
  opening tag without selecting a huge multi-line subtree.
- Shift-click climbs one authored ancestor. `Enter` or a textual "reference"
  action on `use` follows its `href` definition; Back returns to the instance.
- Hover may ghost the linked range/element, but committed selection uses the
  sole red accent and remains until changed.
- The breadcrumb is real navigation, not passive decoration.
- Preview pointer input has two explicit modes. **Inspect** is the default and
  uses clicks for source selection. **Interact** passes hover/click input to the
  document so CSS pseudo-state transitions and event-based SMIL begins can run;
  it preserves the current selection, resumes the document clocks so new
  transitions respond, and exits through `Escape` or the stable top-rail mode
  control. Sandbox navigation/link policy still applies.

### Invalid and stale states

- **Empty:** show concise instruction plus animated and parametric examples;
  never present two unexplained blank panes.
- **Cold invalid:** when no valid preview exists yet, show the located parser or
  capability diagnostic and state that nothing has rendered yet.
- **Warm invalid:** preserve the last valid rendering with a `stale` label and
  locate the current source error.
- **Valid but blank:** distinguish successful rendering with no visible bounds
  from a parse failure and suggest namespace, size/viewBox, and off-canvas
  checks.
- Editor input remains responsive at all times.
- Parse and preview update after a short idle debounce; selection mapping is
  versioned to the same source snapshot.
- On invalid XML after a valid version, preserve the last valid rendering with
  a `stale` label and show the first useful error at the source. Do not blank or
  partially replace the preview.
- When the document becomes valid, replace the preview atomically and restore
  selection by a structural anchor when possible.

## Visual system

The source reference is `~/dev/ref/references/design/yale.md`. Translate it as
a working system, not a mood board:

- warm near-black `#0e0e0d` for the application surface and paper-like ink
  `#e8e3d5` for primary text;
- muted neutral text for secondary evidence and restrained red `#c1432e` only
  for the active cross-representation link, errors, or a genuinely destructive
  action;
- Geist for interface text and Geist Mono for code, numbers, times, units, and
  technical state;
- typography, alignment, whitespace, and 1 px rules instead of cards, pills,
  shadows, glass, or nested rounded containers;
- exact values and units remain visible beside direct manipulation;
- application transitions stay purposeful and generally within 80–200 ms;
  authored SVG motion is controlled by document playback, not aestheticized by
  the shell;
- validity, stale preview, disabled capability, selected source owner, and
  animation family remain visibly evidenced rather than hidden in toasts.

Sliders follow the same discipline. The primary value control is monospaced
text with typing, keyboard increments, and horizontal scrubbing. A thin slider
appears only when the source declares a meaningful bound. Color controls pair a
small swatch with exact text instead of filling the interface with generic
channel sliders.

The desired feeling is a precise bench instrument: dense enough to explain the
document, quiet enough that source and image dominate, and fast enough that
selection and variable manipulation feel physically connected.

## Animation model

### Supported authoring families

1. CSS animations/transitions inside `<style>` or style attributes.
2. SVG animation elements: `animate`, `animateTransform`, `animateMotion`, and
   `set`.

The core does not translate one family into another. It renders browser
semantics and reports the detected family beside the playback state.

### Animation index

Build an animation index early even though the first UI is not a timeline. For
each recognized effect, retain its target, property, source family, declaration
or element range, keyframe/value ranges, timing fields, and current browser
animation when one exists. That index powers “what animates this?”, honest
duration reporting, and source jumps now; it becomes the read model for tracks
if the optional visual extension is pursued.

Unknown selectors, complex cascades, event chains, and script-driven effects
remain renderable where policy permits but are marked read-only or unresolved.
Do not flatten CSS and SMIL into a supposedly universal writable object. The
core may offer family-specific source navigation and literal timing controls.
A shared writable track view belongs to the optional visual extension.

The selected-element facts distinguish authored base value, animated/composed
value, and unresolved value whenever possible. Editing a base value that is
currently overridden by animation must not look like a broken control: name the
override and offer navigation to the winning animation source.

### Playback controller

- **Pause/play:** control CSS/Web Animations objects through the preview
  document's `getAnimations()` result; control the SVG document clock through
  `pauseAnimations()` and `unpauseAnimations()`.
- **Restart:** rebuild the isolated preview from the current valid source so
  both families return to authored initial state.
- **Ordinary source update:** capture the inspection time and running/paused
  state before replacing the preview, then restore them on the rebuilt CSS and
  SMIL clocks. Editing must not throw an author back to zero; only Restart does.
- **Time:** report SVG document time when available. A seek control is shown
  when the document has a meaningful bounded duration or the user supplies an
  inspection horizon. Seeking sets the SMIL document clock and the current time
  of CSS/Web Animation objects together. Event-driven/indefinite cases show
  their limitation rather than inventing a duration.
- **Speed:** defer a global speed control until mixed-clock semantics are
  tested. Per-document duration variables already cover many useful cases.
- **Reduced motion:** workbench transitions stay restrained; preview animation
  begins paused when reduced motion is requested, with an explicit opt-in run.
- **Event interaction:** Inspect mode owns clicks for source navigation;
  Interact mode delivers hover/click to the rendered document for CSS
  transitions/pseudo-states and supported SMIL event begins. Entering Interact
  resumes both animation families; the status rail shows the active mode so
  selecting and triggering are never ambiguous.
- **Reduced motion + interaction:** entering Interact is the user's explicit run
  action when reduced motion began paused; announce that motion will resume
  rather than overriding the preference silently.

### Script boundary

The default preview implements secure animated SVG: declarative animation is
enabled; script execution, inline event handlers, navigation, and external
resources are disabled. The status rail names disabled script rather than
silently implying it ran.

An unsafe script mode is not an MVP checkbox. If later demand justifies it, it
gets a separate opaque-origin execution design, network policy, warning,
message bridge, and threat review.

### Authoring boundary

The first animation writes should be literal and local: selected SMIL timing
attributes and simple CSS declaration/keyframe values with exact ranges. The
core roadmap does not convert CSS and SMIL. If the optional visual extension
ever offers conversion, it is a V6 command with a previewed diff, never a side
effect of changing a control. A visual timeline uses the same source-command
path but is not part of the core roadmap.

Robust support means excellent rendering, control, provenance, diagnostics,
and progressively broader native authoring. It does not mean claiming that
every JavaScript timeline, cascade interaction, or event graph can be safely
round-tripped.

## Variable controls

### Substrate

The initial variable set is literal CSS custom properties authored on the root
`style` attribute. This keeps discovery and exact source replacement bounded
while covering reusable colors, lengths, angles, times, opacity, and numbers.

```svg
<svg style="--radius: 32px; --period: 1.8s; --ink: #c1432e">
  <!-- @control --radius min=8 max=80 step=1 -->
  <!-- ... var(--radius), var(--period), var(--ink) ... -->
</svg>
```

The convention is additive:

- every supported literal variable gets an exact typed control;
- numeric literals support drag-to-scrub and direct typing;
- a valid `@control` directive adds an authored min/max/step and slider;
- color literals get a swatch and exact text;
- unsupported expressions remain visible as source and receive no misleading
  control.

The directive is metadata, not the value. The value always lives in the CSS
declaration. A missing or mismatched directive produces a diagnostic and does
not invent source.

The canonical MVP representation is one directive per comment placed directly
under the root `<svg>`: `@control <name> min=<n> max=<n> step=<n>`. An optional
`unit=<u>` only cross-checks the literal's own unit and never supplies it.
Malformed directives or comments lost to optimization remove only the bounded
slider; the exact value control and SVG behavior remain. Do not support a
second namespaced/data schema in parallel.

### Source updates and undo

Variable controls hold the source version and exact literal range from which
they were derived. Continuous manipulation is throttled to animation frames,
updates only that range, and commits as one undoable gesture. If concurrent
typing invalidates the range, stop the gesture and re-resolve; never write at
an old offset.

`Escape` or `pointercancel` abandons a control gesture, restores its original
literal, and creates no history entry. A committed gesture produces one undo
entry and redo returns its final value.

Numeric writeback retains the replaced token's practical decimal precision and
caps precision for newly generated values. It removes floating-point noise
without altering untouched tokens. Scientific notation and unusual but valid
lexemes are preserved until the user actually changes that value.

### Later extensions

- declarations inside `<style>` rules, using a real CSS parser;
- `@property` type information;
- groups, labels, and durable ranges in an optional sidecar manifest;
- selected-attribute controls that edit literal SVG attributes;
- presets and named variable states.

Do not extend into a private expression graph until evidence shows that CSS
`calc()`, custom properties, and ordinary SVG animation cannot serve the work.

## Architecture

### File envelope

CodeMirror owns the logical editable text, while a small transport envelope
records the originally decoded string, UTF-8 BOM presence, detected line-ending
policy, and dirty state. Exporting an untouched document returns the original
bytes. After an edit, uniform LF/CRLF/CR endings and BOM are preserved; mixed
line endings are normalized deterministically after a visible one-time notice.
This is the truthful boundary of byte fidelity because CodeMirror cannot retain
arbitrary mixed separators in its line model.

Recovery persists source text and filename only after idle. On startup it is
offered with timestamp and discard actions; it is never silently applied.

### Proposed stack

- TypeScript and Vite for the static web application, beginning without a UI
  framework;
- CodeMirror 6 with `@codemirror/lang-xml` for editing and exact Lezer ranges;
- native `DOMParser` for browser-faithful XML validation and DOM construction;
- an iframe sandbox plus Content Security Policy for preview isolation;
- IndexedDB for recovery state and recent local documents;
- Vitest for parser/control units and Playwright for browser, selection,
  animation, security, and accessibility behavior.

Small DOM view modules own the shell, rails, and panels. CodeMirror owns editor
state. A framework-independent session/core layer owns document versions and
derived artifacts. Add a UI framework only if the vertical slice produces
measured state/component complexity that a framework would actually reduce.

The core exposes enough structure for its own features and a later extension
without becoming a second document authority:

- `SourceDocument`: immutable text version and CodeMirror transaction history;
- `SyntaxIndex`: XML/CSS token ranges, diagnostics, and stable structural
  anchors for that version. Index each attribute's name and exact value range;
  add value micro-parsers only for features the core supports;
- `DocumentFacts`: mapped elements, references, controls, and animation records
  needed by the code-forward workbench;
- `EditIntent`: source-version precondition, semantic target, numeric-format
  policy, and intended value; one compiler produces non-overlapping text
  changes, a CodeMirror transaction, selection result, and undo grouping;
- `PreviewSession`: disposable rendered DOM, animation clocks, hit-test maps,
  and overlays.

Core commands replace exact literals for variables and supported animation
fields. The optional extension may add structural and geometry commands behind
the same version/precondition contract. If an operation requires normalization,
preview the affected source or ask explicitly; never silently serialize the
whole document. Unknown elements and attributes stay opaque but preserved.

Selection identity includes an authored element plus an optional inner address
(`kind`, exact range, and ordinal). Core variable and animation fields can use
that address; the visual extension may later address an attribute token,
transform function, path command, or keyframe without changing the shared
selection protocol.

The preview boundary must expose live geometry needed by the core overlay:
`getBBox()`, `getScreenCTM()`, and screen/user-space conversion. Prefer direct
parent inspection only if the Phase 0 sandbox proves safe in all supported
browsers. If security requires an opaque origin, define a narrow geometry
measurement bridge during the security spike rather than weakening isolation.

### Dataflow

```text
Editor transaction
  → source version
    → incremental Lezer tree (ranges, diagnostics, cursor ownership)
    → syntax index (XML, CSS, animation provenance)
    → debounced DOMParser validation
      → valid: document facts + isolated preview DOM + structural range map
      → invalid: diagnostic + retained last-known-good preview

Selection identity
  ↔ CodeMirror reveal/decorations
  ↔ preview hit testing/overlay
  ↔ breadcrumb, animation facts, and variable rail

Variable or animation-control gesture
  → version-checked source command
    → one CodeMirror transaction / undo group
      → normal editor transaction flow above
```

### Suggested modules

```text
src/
  app/              shell, rails, responsive layout
  editor/           CodeMirror setup, commands, decorations
  document/         versions, parse result, diagnostics, persistence
  syntax/           XML/CSS ranges and structural anchors
  model/            immutable element/reference/animation facts used by core
  commands/         versioned source patches for variables/animation controls
  mapping/          authored nodes, DOM alignment, selection anchors
  preview/          sandbox, CSP, rendering, hit testing, overlay
  animation/        family adapters, provenance index, clocks, source controls
  controls/         custom-property discovery, directives, source edits
  test-fixtures/     static, animated, parametric, hostile, and large SVGs
```

Do not create a package workspace or global state library until code needs the
boundary. The folder seams are enough for the first vertical slice. Do not
implement extension modules in Phase 1; define the small shared contracts and
prove one end-to-end variable or animation command.

### Mapping contract

- Identity is valid only for one source version.
- A mapped authored element has an exact full range and opening-tag range.
- Supported CSS declarations and animation fields gain exact subranges as
  their core tools arrive.
- DOM alignment checks name and structure rather than trusting list position
  alone.
- Mapping failures degrade per element and emit diagnostics; they do not
  disable an otherwise valid preview.
- Preview-only nodes never enter the source map.
- Selection restoration uses a structural anchor (expanded name, authored
  ancestry, sibling ordinal, optional `id`) and may honestly fail after edits.

### Source-mutation contract

- Every command is based on one source version and refuses stale ranges.
- Undo/redo belongs to CodeMirror, including continuous control
  gestures coalesced into one semantic edit.
- Reparse after every committed command; never patch a derived projection in
  hope that it still matches the source.
- Preserve unsupported/unknown syntax byte-for-byte outside the command range.
- Separate lossless edits from normalizing operations in the UI and tests.
- Test emitted source, preview result, selection restoration, and undo as one
  contract—not as independent features.
- Opening, inspecting, playing, seeking, and exporting without an edit must be
  byte-identical. Golden fixtures enforce this for BOM, CRLF/mixed EOLs,
  unusual numbers, entities, whitespace, quotes, CDATA, comments, and inline
  CSS. After an edit, the declared EOL/BOM policy applies.

### Security contract

- Parse as SVG/XML, reject parser errors and document type declarations in the
  first release.
- Require the parsed root to be an SVG element in
  `http://www.w3.org/2000/svg`; namespace-less pasted XML receives a specific
  diagnostic rather than a blank preview or silent source rewrite.
- Preview in an iframe with script disabled and parent inspection tested.
- Keep `srcdoc` limited to a trusted static shell and import the already
  validated XML document element with `importNode()`. Never put user SVG text
  through HTML `srcdoc` or `innerHTML` parsing.
- Apply a CSP that denies network sources and top-level navigation; install a
  parent-owned link guard for Interact mode.
- Treat `foreignObject`, links, embedded media, external `href`, inline event
  attributes, and scripts as explicit security fixtures.
- Sanitization may remove prohibited capability in the preview, but must never
  rewrite the editor source. Show a capability diagnostic when preview differs.
- Export the original current source, never the preview DOM.

## Quality and success measures

Product:

- A first-time developer can paste an SVG, identify a rendered element's code,
  change it, pause its animation, tune a variable, and download the result
  without documentation.
- A returning expert can operate open/save, search, source/preview focus,
  selection ancestry, play/pause, and variable editing by keyboard.
- The downloaded source differs only where the user explicitly edited it.

Optional visual-extension progress is evaluated separately; it does not count
toward core success or justify adding toolbar surface to the workbench.

Technical budgets to validate, then adjust from evidence:

- typing remains frame-responsive independently of preview work;
- a 100 KB / 1,000-element valid fixture reaches the preview within 100 ms
  after the debounce on a representative laptop;
- a 500 KB / 5,000-element fixture remains usable and updates within 500 ms;
- selection overlay does not materially lower a 60 fps authored animation;
- hostile fixtures make zero script executions, network requests, navigations,
  or parent-DOM mutations;
- Chrome, Firefox, and Safari agree on the documented animation and selection
  contract, or the UI names the browser-specific limitation.

## Open product questions

1. Is the first audience primarily people hand-authoring animation, people
   debugging exported SVG, or learners? The same core serves all three, but
   examples and onboarding should pick one lead.
2. Should the working name remain `svg`, or should the product claim a more
   searchable identity around inspectable/moving SVG?
3. Is direct filesystem save important enough to foreground despite uneven
   browser support, or is open/download plus recovery sufficient initially?
4. Do real target files favor CSS or SVG animation elements? That determines
   how much timeline/seek work earns an early place.
5. Do real optimizer-heavy workflows eventually justify replacing root comment
   control directives with an optional sidecar or namespaced/data form?
6. Does observed demand justify starting the separate visual editing extension
   at all? If so, its own roadmap chooses among tree/inspector, geometry, and a
   writable timeline without changing the core positioning.
